Fortune 500 Tech Stack Research

Complete Process Guide & Best Practices
Last Updated: January 29, 2026

📋 Executive Summary

This document outlines the complete research process for maintaining accurate Fortune 500 technology stack data. Following this guide will prevent data mismatches between markdown files, HTML dashboards, and summary statistics.

Key Principle: Single source of truth in markdown → Generate HTML → Validate consistency

❌ Problems Encountered

Issue #1: Stat Tile vs Dropdown Mismatch

Symptoms:

  • Stat tiles showed: Salesforce (139), ServiceNow (131), Jira (60), Slack (33)
  • Dropdown counts showed: Salesforce (119), ServiceNow (113), Jira (33), Slack (14)

Root Cause: Batch files contained summary statistics (expected totals) but actual company entries had incomplete app data. The generate_html.py script pulled hardcoded stats from markdown summary while dropdown counted actual company data.

Issue #2: Missing Company Details

Symptoms:

  • Markdown claimed 201 companies but only had 65 detailed entries
  • Companies 66-201 were missing from markdown
  • HTML only showed 65 companies initially

Root Cause: Batch update scripts only updated summary statistics without adding actual company research sections to markdown.

Issue #3: Markdown vs HTML Discrepancies

Symptoms:

  • CITIGROUP markdown said Jira/Confluence "NOT CONFIRMED" but HTML showed them as confirmed
  • EXXON MOBIL markdown said ServiceNow/Slack/Jira/Confluence "No evidence" but HTML showed confirmed
  • Intel and Apple had incomplete target app lists

Root Cause: Markdown research was detailed but conservative, while HTML extraction logic was more aggressive in marking apps as confirmed.

Issue #4: Google Apps Confusion

Symptoms:

  • Gmail and Google Drive tracked separately for some companies
  • Google Cloud tracked for infrastructure but confused with Gmail/Drive
  • Multiple reversions between Gmail/Drive and Google Cloud

Root Cause: Unclear distinction between Google Workspace apps (Gmail, Google Drive as SaaS products) vs Google Cloud Platform (infrastructure).

✅ Correct Research Workflow

Step 1: Research Individual Company

Conduct thorough web research for each company using:

  • Company press releases and blog posts
  • Case studies from software vendors
  • Job postings mentioning specific tools
  • LinkedIn profiles of employees
  • Investor presentations and annual reports
⚠️ Warning: Be conservative! Only mark apps as "CONFIRMED" if you have solid evidence. Use "NOT CONFIRMED" or "NO EVIDENCE" when uncertain.

Step 2: Document in Markdown with Consistent Format

Use the following structure for EVERY company:

## [NUMBER]. [COMPANY NAME]

### Tech Stack

**[App Name]** ✓
- [Evidence detail 1]
- [Evidence detail 2]

**[App Name]** ✓
- [Evidence detail]

**Other Technologies:**
- Microsoft 365/Azure
- AWS
- SAP
- Google Cloud
- Workday
- Oracle

---
Format Requirements:
  • Use **App Name** ✓ for CONFIRMED target apps only
  • List "Other Technologies" separately (not target apps)
  • Keep target apps to: Salesforce, ServiceNow, Jira, Confluence, Slack, Gmail, Google Drive, Gong, Dropbox, Box
  • Add --- separator after each company

Step 3: Update Summary Statistics MANUALLY

After adding companies, count and update the summary section:

## Summary Statistics (Updated: [TOTAL_COUNT] Companies)

### Target Apps Usage Confirmed:

**Salesforce**: [COUNT] companies
**ServiceNow**: [COUNT] companies
**Jira**: [COUNT] companies
**Confluence**: [COUNT] companies
**Slack**: [COUNT] companies
**Gmail**: [COUNT] companies
**Google Drive**: [COUNT] companies
**Gong**: [COUNT] companies
**Dropbox**: [COUNT] companies
**Box**: [COUNT] companies
✓ Best Practice: Use a validation script to count apps from markdown and compare with summary section before generating HTML.

Step 4: Generate HTML Dashboard

Run the HTML generator:

python generate_html.py

This script should:

  • Parse markdown file to extract all company sections
  • Look for **App Name** ✓ pattern to identify target apps
  • Check for negative indicators (NOT CONFIRMED, NO EVIDENCE, ✗)
  • Count actual apps from company entries (not from summary)
  • Generate HTML with correct counts

Step 5: Validate Consistency

Run validation checks:

Step 6: Manual Spot Checks

  • Open HTML dashboard in browser
  • Verify stat tiles match dropdown counts
  • Search for 3-5 random companies and verify their apps
  • Test filtering by different apps
  • Check that total companies count is correct

📊 Data Quality Rules

Rule #1: Single Source of Truth

The markdown file is the ONLY source of truth. HTML is generated FROM markdown, never edited directly.

Rule #2: Confirmed vs Not Confirmed

Only use **App** ✓ if you have solid evidence. When in doubt, document as "NOT CONFIRMED" with explanation.

Rule #3: Target Apps Only

Limit target apps to the 10 specified: Salesforce, ServiceNow, Jira, Confluence, Slack, Gmail, Google Drive, Gong, Dropbox, Box.

Rule #4: Other Technologies

Infrastructure and other apps go in "Other Technologies" section, not as target apps with checkmarks.

Rule #5: Google Apps Distinction

Gmail/Google Drive: SaaS products (target apps)
Google Cloud: Infrastructure (other technology)

Rule #6: Stats Match Reality

Summary statistics MUST match actual count of companies with each app. Generate counts, don't guess.

🔄 Batch Processing Guidelines

⚠️ Avoid Batch Statistics-Only Updates

Do NOT create batch files that only update summary statistics without adding actual company research to markdown. This causes the mismatch problem.

Correct Batch Process:

Step Action Validation
1 Research N companies (e.g., 10 companies) Have detailed notes for each
2 Add all N company sections to markdown Each has Tech Stack section with **App** ✓ format
3 Count apps from all companies in markdown Use grep/script to count, not manual
4 Update summary section with new counts Total should be previous + N
5 Regenerate HTML HTML count should match markdown count
6 Verify stat tiles = dropdown counts Open dashboard and check
✓ Template for Batch Script: 
import re

# 1. Read markdown
with open('company_technology_stack_analysis.md', 'r', encoding='utf-8') as f:
    content = f.read()

# 2. Add new company sections
new_companies = """
## 66. JOHNSON & JOHNSON

### Tech Stack

**Salesforce** ✓
- Evidence detail

**ServiceNow** ✓
- Evidence detail

**Other Technologies:**
- Microsoft 365/Azure
- SAP

---
"""

# 3. Insert before summary section
summary_pos = content.find('## Summary Statistics')
content = content[:summary_pos] + new_companies + content[summary_pos:]

# 4. Count ALL apps from markdown (not hardcoded!)
salesforce_count = len(re.findall(r'\*\*Salesforce\*\* ✓', content))
servicenow_count = len(re.findall(r'\*\*ServiceNow\*\* ✓', content))
# ... count all apps

# 5. Update summary with actual counts
content = re.sub(r'\*\*Salesforce\*\*: \d+ companies',
                 f'**Salesforce**: {salesforce_count} companies', content)
# ... update all apps

# 6. Save
with open('company_technology_stack_analysis.md', 'w', encoding='utf-8') as f:
    f.write(content)

print(f'Added companies, verified counts')

🔍 Validation Scripts

Script 1: Count Validation

#!/usr/bin/env python3
import re

with open('company_technology_stack_analysis.md', 'r', encoding='utf-8') as f:
    content = f.read()

# Count company sections
companies = len(re.findall(r'^## \d+\.', content, re.MULTILINE))

# Count each target app
apps = {
    'Salesforce': len(re.findall(r'\*\*Salesforce\*\* ✓', content)),
    'ServiceNow': len(re.findall(r'\*\*ServiceNow\*\* ✓', content)),
    'Jira': len(re.findall(r'\*\*Jira\*\* ✓', content)),
    'Confluence': len(re.findall(r'\*\*Confluence\*\* ✓', content)),
    'Slack': len(re.findall(r'\*\*Slack\*\* ✓', content)),
    'Gmail': len(re.findall(r'\*\*Gmail\*\* ✓', content)),
    'Google Drive': len(re.findall(r'\*\*Google Drive\*\* ✓', content)),
    'Gong': len(re.findall(r'\*\*Gong\*\* ✓', content)),
    'Dropbox': len(re.findall(r'\*\*Dropbox\*\* ✓', content)),
    'Box': len(re.findall(r'\*\*Box\*\* ✓', content)),
}

print(f'Total Companies: {companies}')
print('\nApp Counts:')
for app, count in apps.items():
    print(f'  {app}: {count}')

# Extract summary stats and compare
summary_match = re.search(r'Summary Statistics.*?(\d+) Companies', content)
if summary_match:
    summary_total = int(summary_match.group(1))
    if summary_total != companies:
        print(f'\n❌ MISMATCH: Summary says {summary_total} but found {companies}')
    else:
        print(f'\n✓ Summary total matches actual count')

# Check each app in summary
for app, actual_count in apps.items():
    pattern = rf'\*\*{re.escape(app)}\*\*: (\d+) companies'
    match = re.search(pattern, content)
    if match:
        summary_count = int(match.group(1))
        if summary_count != actual_count:
            print(f'❌ {app}: Summary says {summary_count} but found {actual_count}')
        else:
            print(f'✓ {app}: {actual_count} (matches)')

Script 2: HTML Consistency Check

#!/usr/bin/env python3
import json
import re

# Read HTML
with open('company_technology_stack_analysis.html', 'r', encoding='utf-8') as f:
    html = f.read()

# Extract companies data
match = re.search(r'const companies = (\[.*?\]);', html, re.DOTALL)
companies = json.loads(match.group(1))

# Count apps in HTML data
html_counts = {
    'Salesforce': sum(1 for c in companies if 'Salesforce' in c.get('apps', [])),
    'ServiceNow': sum(1 for c in companies if 'ServiceNow' in c.get('apps', [])),
    'Jira': sum(1 for c in companies if 'Jira' in c.get('apps', [])),
    'Slack': sum(1 for c in companies if 'Slack' in c.get('apps', [])),
}

# Extract stat tiles
tiles = {
    'Salesforce': int(re.search(r'id="salesforce-count">(\d+)<', html).group(1)),
    'ServiceNow': int(re.search(r'id="servicenow-count">(\d+)<', html).group(1)),
    'Jira': int(re.search(r'id="jira-count">(\d+)<', html).group(1)),
    'Slack': int(re.search(r'id="slack-count">(\d+)<', html).group(1)),
}

print(f'HTML has {len(companies)} companies\n')
print('Stat Tiles vs Actual Data:')
for app in html_counts.keys():
    if tiles[app] == html_counts[app]:
        print(f'✓ {app}: {tiles[app]} (matches)')
    else:
        print(f'❌ {app}: Tile shows {tiles[app]} but data has {html_counts[app]}')

⚠️ Common Mistakes to Avoid

❌ Mistake #1

Updating only statistics without company details

Creates phantom companies that exist in counts but not in data.

❌ Mistake #2

Hardcoding statistics in HTML

Stats should be counted from actual company data, not copied from markdown summary.

❌ Mistake #3

Marking apps as confirmed without evidence

Be conservative. "NOT CONFIRMED" is better than false positives.

❌ Mistake #4

Editing HTML directly

HTML is generated. Always edit markdown, then regenerate HTML.

❌ Mistake #5

Inconsistent formatting

Use exact format: **App** ✓ not **App**✓ or **App** ✅

❌ Mistake #6

Not validating after updates

Always run validation scripts after making changes.

✓ Pre-Commit Checklist

Before considering your update complete, verify all items:

  • All researched companies have detailed sections in markdown
  • Each company uses consistent **App** ✓ format
  • Summary statistics match actual grep counts from markdown
  • HTML has been regenerated using generate_html.py
  • HTML stat tiles match dropdown filter counts exactly
  • Total company count is consistent across markdown summary, HTML tiles, and HTML data
  • Spot-checked 5 random companies in HTML dashboard
  • Ran validation scripts with no errors
  • No "NOT CONFIRMED" apps are marked with ✓ checkmarks
  • Google Cloud vs Gmail/Google Drive distinction is clear
