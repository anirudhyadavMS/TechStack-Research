RESEARCH CHALLENGES & LIMITATIONS
================================================================================

1. DATA AVAILABILITY
   - Public information varies by company
   - Some companies don't disclose tech stack
   - Job postings are best indicator but may be outdated

2. RATE LIMITING
   - Web research APIs have limits
   - Too many parallel requests = 429 errors
   - Solution: Batch size of 10 works reliably

3. VERIFICATION
   - Multiple sources preferred for confirmation
   - Some tools mentioned in passing vs. actively used
   - Conservative approach: Only count confirmed usage

4. PRIVATE COMPANIES
   - Less public information available
   - Examples: Cargill, Mars, HEB
   - Require more extensive research


TIPS FOR CONTINUING THE RESEARCH
================================================================================

1. MAINTAIN CONSISTENCY
   - Use same research standards
   - Same batch update pattern
   - Keep markdown format consistent

2. VERIFY BEFORE UPDATING
   - Check agent results for confirmation
   - Look for multiple source mentions
   - Flag uncertain findings

3. REGENERATE HTML REGULARLY
   - After each batch or every 2-3 batches
   - Ensures dashboard stays current
   - Validates markdown parsing works

4. TRACK RATE LIMITS
   - If 429 errors occur, reduce batch size
   - Wait 10-15 minutes before retrying
   - Consider splitting large batches

5. BACKUP REGULARLY
   - Save markdown file frequently
   - Keep previous batch scripts
   - Version control recommended (git)
